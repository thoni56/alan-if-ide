== A folder, not a project

Starting a new game is easy, you only need a folder and the IDE. There is no project, no wizard, and no template. These are all things that might change in the future, but for now they are not needed.

Since a game is contained in a folder, you open it with menu:File[Open Folder...].
The folder can be empty, or it can already hold some files.

The thing that makes a folder a game is the presence of a `.alan` file. The IDE looks for one in the folder, and if it finds one it treats the folder as a game.

A game needs at least one `.alan` file.
You might also create one or more "Alan import" files which have an `.i` extension.
To start you won't need any, but you can add some later.
The IDE does not care about any other files, and it does not, yet, handle sub-folders.

To create files you use the Explorer's New File command, or the menu:File[New File] command.
This will create an empty file in the folder you have open, and you can give it any name you like.

== The main file and Start At

The smallest possible Alan game that compiles and run is a single location and a start clause:

[source,alan]
----
The kitchen Isa location.
End The kitchen.

Start At kitchen.
----

Create a file with a `.alan` extension, and put the above text in it.

If you have set up the IDE completely, especially the Alan compiler and interpreter, you can run the game with menu:Run[Run Game] or the F5 key.

[.fold-in]
.To fold in
****
There is no menu:Run[Run Game] and nothing on F5.
Play is the ▶ button at the top right of the editor, *Play* on the right-click menu, or *Alan IF: Play* in the Command Palette.
Play saves all unsaved files first.
Source: `package.json` and `play.ts`.
****

[TIP]
====
You can check if the setup is correct by looking at the status bar. Hover over the curly braces beside the "Alan" indicator where you can see the most important settings and their values. The braces will also have a little dot on them if there is something requiring your attention. You can also use the menu:Alan[Check Settings] command.

If that does not work, check the IDE's Output panel for errors, and see the troubleshooting section in section{troubleshooting}.
====

You should now see a terminal window in the IDE, usually at the bottom, with the text "The kitchen" and a prompt.
That's the game running, and you can type commands at the prompt.

The game currently has no other locations, no objects, and no verbs, so the only way to quit is to close the that terminal window.

== Watching it compile as you type

There is no "compile" button, so you cannot run the compiler yourself.
Instead the game is automatically analysed and compiled on every keystroke, from the editor, unsaved text and all.

To try this out, type a few random characters in the editor.

If you type something that is not valid Alan code, you will get some markers in the editor area. You can hover it to see its description, or use menu:View[Problems] to show the "Problems" tab.
